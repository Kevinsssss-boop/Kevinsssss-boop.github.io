薪酬合规审阅工具Payroll Compliance Review Tool

一份涉及多国薪酬规则的实务手册，需要被拆成若干模块，分给不同的人逐条核对、 标注问题、写明理由，最后汇总回一张可交付的 Excel。原本这件事靠互相传表格完成。 A multi-country payroll reference handbook had to be split into modules, assigned to different reviewers, annotated line by line, and merged back into one deliverable spreadsheet. The original process was people mailing spreadsheets to each other.

问题在哪The problem

手册本身是一张几百行的 Excel，每一行是一条薪酬实务规则。审阅要做的事是： 判断这条规则在当前国家/地区还成不成立、附上依据、必要时写明修改建议。 多人并行时，Excel 提供的协作能力基本为零——谁改了哪一格看不出来，两个人同时打开就互相覆盖， 一天下来只能靠来回发文件。 The handbook is a few hundred rows of Excel, one payroll rule per row. Reviewing means deciding whether each rule still holds, attaching a source, and proposing a change where needed. Excel gives you almost nothing for parallel work: no per-cell attribution, and two people editing at once overwrite each other. The day degenerates into mailing files back and forth.

做成了什么What it became

  • 把审阅拆成有归属的任务。手册按模块切分，每个模块分配给具体的校验人； 工具只让被分配的人改自己那部分，其他人看得到进展但改不了。 Review became assigned work. The handbook is split into modules, each assigned to a named reviewer. Only the assignee can edit their part — everyone else can see progress but not touch it.
  • 标注带格式和理由。每个字段用富文本编辑，可以加粗、标色、写删除线， 表达「这句要改」而不只是「这格不对」。 Annotations carry formatting and reasoning. Each field is a rich-text editor, so a reviewer can bold, colour or strike through — expressing this clause should change, not just this cell is wrong.
  • 审阅状态是一等公民。待审阅 / 已确认 / 需修改 / 待讨论四种状态贯穿界面与导出， 项目进度按「还有多少字段没确认」算，而不是凭感觉。 Status is first-class. Four states (pending / confirmed / needs change / to discuss) run through both the UI and the export, so progress means "how many fields are still unconfirmed" rather than a guess.
  • 导出回原格式。审阅结果写回与源文件同结构的 Excel， 保留原有列宽与公式结构，可以直接交付给下一环节。 It exports back to the original format. Results are written into a workbook matching the source structure, preserving column widths and formula layout, ready to hand to the next step.

我做了什么My part

这个工具的基础版本已经存在，但停留在「能跑」的阶段：没有测试、没有权限校验、 若干路径在出错时会静默丢数据。我负责的是把它推到可长期使用的程度—— A basic version already existed, but it stopped at "it runs": no tests, no access control, and several paths that silently lost data when something went wrong. My work was getting it to a state that could be relied on —

  • 补上授权。有 8 个接口此前不校验任何权限，只要知道 URL 就能读写别人的项目。 加了统一的权限判断：项目创建者或被分配者才能访问，写操作额外收紧。 Added authorisation. Eight endpoints checked nothing — knowing the URL was enough to read or write someone else's project. Added a single access check: only the project owner or an assignee may reach it, with writes restricted further.
  • 修掉会丢数据的上传路径。原来的上传顺序是「先删旧审阅记录 → 再解析新文件」， 解析一旦失败，此前所有人工审阅成果就没了，而且提示还是「上传失败」——用户不知道自己丢了什么。 改成先解析、成功后再替换，失败则原样保留。 Fixed a data-losing upload path. The original order was "delete existing review records → parse the new file". One parse failure and every manual review was gone — while the message just said "upload failed", so nobody knew what they'd lost. Now the file is parsed first and only swapped in on success.
  • 修掉会「报成功但不生效」的保存。SQLite 写锁竞争时，保存操作会回滚整个事务 却仍然返回成功。用户改了一下午，界面上显示已保存，实际上一条都没落库。 Fixed saves that reported success without persisting. Under SQLite write-lock contention the save rolled back its whole transaction and still returned success. A reviewer could work all afternoon, see "saved" every time, and have nothing in the database.
  • 修掉导出会毁掉公式的路径。导出时的 data_only 参数会让 openpyxl 读取公式的缓存值并在写回时把公式整个替换掉——程序生成的表里没有缓存值，于是公式直接变成空白。 Fixed an export path that destroyed formulas. The data_only flag makes openpyxl read cached formula results and overwrite the formulas themselves. For programmatically generated sheets there is no cached value, so formulas simply became blank.
  • 补测试。权限矩阵、导出公式保全、空模块不被误判为「已完成」等， 都写成了测试，防止以后改回去。 Added tests. The permission matrix, formula preservation on export, and not marking an empty module "complete" are all covered now, so they can't quietly regress.

一处我改了默认行为的地方One deliberate behaviour change

把「清空」的含义改成了「回到未修改」。原来把某个字段删空后， 空字符串会被当成一个有效的人工修改值，于是界面上不再显示原始提取内容、导出该格也变空白， 而且重新导入文件后仍然如此——等于一次误删无法撤销。改成清空即恢复原始值； 代价是「人工确认为空」与「未修改」不再可区分，这在此工具的用法里是更合理的取舍。 Clearing a field now means "revert to unmodified". Previously an emptied field stored an empty string as a valid manual override — so the original content stopped showing, the export came out blank, and re-importing the file didn't help. One accidental delete was permanent. Now clearing reverts to the source value. The cost is that "confirmed empty" and "untouched" become indistinguishable, which is the better trade for how this tool is actually used.

为什么源码不公开Why the source is private

这个工具是围绕真实业务的薪酬合规口径写的，手册内容、字段体系、业务规则都属于内部信息。 这里展示的是它的设计与工程取舍，不含任何业务数据。 The tool is built around a real compliance framework — the handbook content, the field structure and the business rules are all internal. What's shown here is the design and the engineering decisions, with no business data.
